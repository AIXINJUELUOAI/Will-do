## 1. 项目定位

Will do 是一款 Android 智能日历助手，核心目标是把用户输入、系统事件和天气信息稳定转成可展示、可提醒、可同步、可备份的数据。

主要能力：

- 日程：新增、编辑、完成、归档、重复、课程、特殊类型展示。
- 识别：文本、图片、OCR、短信、剪贴板码类识别。
- 随口记：语音记录、转写、建议、待办状态、详情页。
- 便签：Markdown 编辑、附件、导入导出。
- 天气：实时天气、小时/每日预报、官方预警、本地风险提醒、天气详情页。
- 通知：普通通知、闹钟提醒、天气通知、实况/胶囊展示。
- 桌面组件：日程组件、天气组件、课程组件。
- 悬浮入口：悬浮窗、侧边栏、快捷磁贴、图片分享、语音入口。
- 平台能力：无障碍、Shizuku、Root 检测、Xposed/HyperOS/Flyme 适配。

当前主线不包含 `:ai-engine` 模块构建。根目录下的 `ai-engine` 如存在，不属于当前 `settings.gradle.kts` include 范围。

## 3. 当前目录结构

主源码入口：

```text
app/src/main/java/com/antgskds/calendarassistant/
+-- App.kt
+-- MainActivity.kt
+-- app/
+-- feature/
+-- platform/
+-- shared/
```

### 3.1 `app/`

`app/` 是应用级装配、运行时和全局 UI 状态层。

主要内容：

```text
app/
+-- runtime/
|   +-- AppRuntimeCoordinator.kt
|   +-- migration/LegacyDataMigrationCoordinator.kt
+-- ui/
    +-- navigation/
    +-- prompt/
    +-- state/MainViewModel.kt
    +-- state/SettingsViewModel.kt
    +-- theme/
```

职责：

- `App.kt` 负责依赖装配、启动初始化、全局事件订阅。
- `MainActivity.kt` 负责主 Compose 容器、导航和系统栏。
- `MainViewModel` / `SettingsViewModel` 负责主 UI 与设置 UI 的状态连接。
- `runtime` 放启动例程、迁移、权限恢复、后台订阅等应用级流程。

### 3.2 `feature/`

`feature/` 是业务功能域，新增业务代码优先放这里。

当前功能域：

```text
feature/
+-- appearance/
+-- backup/
+-- capsule/
+-- home/
+-- note/
+-- notification/
+-- quickmemo/
+-- recognition/
+-- schedule/
+-- settings/
+-- update/
+-- weather/
```

推荐子结构：

```text
feature/<domain>/
+-- api/          对外契约，适合跨模块调用
+-- application/  用例、门面、协调器
+-- data/         Repository、DAO、数据源、缓存
+-- domain/       领域模型和纯业务规则
+-- ui/
    +-- contract/  UiState / UiAction
    +-- connector/ ViewModel/App 到 UI contract 的连接层
    +-- render/    可被 flavor host 委托的 UI 渲染
```

不是每个 feature 都必须完整拥有这些目录。小功能保持轻量即可。

### 3.3 `platform/`

`platform/` 放 Android 系统、ROM、外部入口和副作用代码。

当前主要目录：

```text
platform/
+-- accessibility/
+-- calendar/
+-- capsule/
+-- clipboard/
+-- entry/
+-- floating/
+-- notification/
+-- permission/
+-- receiver/
+-- tile/
+-- widget/
+-- xposed/
```

职责边界：

- 可以调用 Android Framework、系统服务、Intent、Receiver、Service、Widget、Xposed。
- 不应承载核心业务规则。
- 需要写入日程、随口记、设置时，应回到 `feature` 的 application/API/facade。

注意：部分外部入口物理目录已迁移到 `platform`，但 package 仍故意保持旧 FQCN，例如：

- `com.antgskds.calendarassistant.core.service.*`
- `com.antgskds.calendarassistant.calendar.jobs`
- `com.antgskds.calendarassistant.calendar.receivers`

这是为了兼容 Manifest、快捷方式、Worker、系统调度或历史外部入口。不要仅为了“包名好看”修改这些 FQCN。

### 3.4 `shared/`

`shared/` 放稳定契约、公共工具、公共 UI 组件和隔离的第三方算法源码。

当前主要目录：

```text
shared/
+-- content/
+-- event/
+-- management/
+-- operation/
+-- query/
+-- ui/
+-- util/
+-- vendor/
```

职责：

- `operation/`：写操作契约，例如 `CalendarOperationApi`、`IngestCommandApi`。
- `query/`：读模型契约，例如 `SettingsQueryApi`、`WidgetScheduleQueryApi`。
- `event/`：领域事件总线和事件类型。
- `content/`：内容来源和展示契约。
- `ui/`：公共 Compose 组件、动效、触感、布局。
- `vendor/`：隔离的第三方算法源码，例如 Material Color 工具。

`shared` 应尽量保持无业务副作用。公共契约可以放这里，具体实现应回到 `feature` 或 `platform`。

### 3.5 `:location`

`:location` 是独立 Android Library，负责定位能力。

```text
location/src/main/java/com/antgskds/calendarassistant/location/
+-- AndroidLocationProvider.kt
+-- LocationProvider.kt
```

设计原则：

- `:location` 不依赖 `:app`。
- `:location` 不包含天气业务。
- 它只提供定位权限、设备坐标、精度、时间和来源等基础信息。
- 天气功能由 `feature/weather` 消费定位结果。

## 4. UI 结构

UI 分三层：

```text
feature/app/platform main source set
    contract / connector / material renderer
        ^
        |
native 或 hyperos flavor host
```

当前 `native` 和 `hyperos` source set 中的 host 文件保持对称。架构检查会校验两边 host 是否缺失。

维护规则：

1. `ui/contract` 不依赖具体 ViewModel。
2. flavor host 不直接依赖 Repository、DAO、Center、ViewModel。
3. UI edition 只能通过 Gradle flavor 选择，不恢复运行时 `UiStyle` 切换。
4. `BuildConfig.UI_EDITION` 不得参与业务、数据库、备份、通知协议分支。
5. HyperOS 风格优化应优先替换 renderer/host，不改变业务数据结构。

## 5. 数据与存储

### 5.1 Room 主库

Room 数据库：

```text
feature/schedule/data/db/EventsDatabase.kt
database name: events.db
```

当前承载：

- `events`
- `event_types`
- `event_attachments`
- `notes`
- `quick_memos`
- `quick_memo_suggestions`

核心原则：

- `events.db` 是 App 的主要业务事实源。
- Android Calendar Provider 是系统日历互通层，不是唯一事实源。
- UI、Receiver、Service 不直接写 DAO。
- 日程写入应走 `ScheduleFacade` / `ScheduleStoreGateway` / store 链路。

### 5.2 设置

设置模型：

```text
feature/settings/data/model/MySettings.kt
feature/settings/data/SettingsDataSource.kt
feature/settings/data/SettingsRepository.kt
```

持久化 key：

```text
settings_json
```

设置通过 `SettingsRepository` 对外暴露 `Flow<MySettings>`，UI 通过 `SettingsViewModel` 消费。

### 5.3 文件与附件

主要文件类数据：

- 日程附件：`feature/schedule/data/attachment/EventAttachmentManager.kt`
- 便签附件：`feature/note/data/attachment/NoteAttachmentStore.kt`
- 随口记音频/模型缓存：`feature/quickmemo/data/audio`、`feature/quickmemo/data/asr`
- 诊断日志：`feature/settings/diagnostics`

附件不要塞进 `Event.description`，应走专门的附件表或文件存储。

## 7. 核心业务链路

### 7.1 日程链路

```text
UI / 识别 / 通知动作 / 悬浮窗
  -> ScheduleFacade
  -> ScheduleStoreGateway
  -> StoreDispatcher / StoreRootNode
  -> EventsDatabase
  -> Calendar Provider / Alarm / Widget / Notification
```

日程模型位于：

```text
feature/schedule/domain/model/Event.kt
feature/schedule/domain/model/EventType.kt
feature/schedule/domain/model/EventAttachment.kt
```

课程模型位于：

```text
feature/schedule/domain/course/
```

课程最终统一映射为日程事件，不再维护独立主存。

### 7.2 识别与入库

```text
文本 / 图片 / OCR / 短信 / 剪贴板
  -> RecognitionOrchestrator
  -> RemoteSemanticProvider / RegexScheduleRecognizer / OCR provider
  -> RecognitionDraft
  -> IngestPipeline
  -> ScheduleIngestWriter
  -> ScheduleFacade
```

识别相关目录：

```text
feature/recognition/application/
feature/recognition/domain/
feature/recognition/ingest/
feature/recognition/ui/
```

当前主线语义识别以远程 AI、规则识别和 ML Kit OCR 为主。

### 7.3 随口记

```text
QuickMemoVoiceCaptureService / QuickMemo UI
  -> QuickMemoFacade
  -> QuickMemoRepository
  -> QuickMemoDao
  -> quick_memos / quick_memo_suggestions
```

随口记目录：

```text
feature/quickmemo/application/
feature/quickmemo/data/
feature/quickmemo/domain/
feature/quickmemo/ui/
platform/floating/QuickMemoVoiceCaptureService.kt
```

Root/未 Root 设备上的行为差异应优先检查服务启动、录音权限、前台服务类型、数据库迁移和升级保留数据。

### 7.4 天气

```text
Settings / Worker / 手动刷新
  -> WeatherRepository
  -> 和风天气 API / 位置来源
  -> WeatherData cache
  -> Weather UI / Floating / Notification / Capsule / Widget
```

天气目录：

```text
feature/weather/domain/
feature/weather/data/
feature/weather/ui/
```

天气通知点击路由应回到天气详情页。天气能力包括实时天气、预报、官方预警、本地风险分析和天气组件。

### 7.5 通知与实况

```text
业务事件
  -> NotificationOrchestrator
  -> AndroidNormalNotificationPublisher / SystemAlarmGateway
  -> NotificationAlarmReceiver / EventActionReceiver
```

实况/胶囊：

```text
feature/capsule/
platform/capsule/
platform/xposed/
shared/management/resource/notification/display/live/
```

普通通知和实况展示共享展示模板，但发布渠道不同。

### 7.6 桌面组件

```text
Schedule changed / Settings changed
  -> WidgetController
  -> LocalWidgetScheduleQueryApi
  -> WidgetScheduleSnapshot
  -> ScheduleWidgetRenderer / WeatherWidgetRenderer / CourseWidgetRenderer
  -> AppWidgetManager
```

组件相关代码在：

```text
platform/widget/
```

Renderer 只负责 RemoteViews 渲染，不写业务数据。

## 8. Manifest 与外部入口

主要权限：

- 网络、定位：`INTERNET`、`ACCESS_COARSE_LOCATION`、`ACCESS_FINE_LOCATION`
- 通知：`POST_NOTIFICATIONS`、`POST_PROMOTED_NOTIFICATIONS`
- 音频：`RECORD_AUDIO`
- 闹钟：`SCHEDULE_EXACT_ALARM`、`USE_EXACT_ALARM`、`SET_ALARM`
- 前台服务：`FOREGROUND_SERVICE*`
- 系统日历：`READ_CALENDAR`、`WRITE_CALENDAR`
- 悬浮窗：`SYSTEM_ALERT_WINDOW`
- 短信：`RECEIVE_SMS`、`READ_SMS`
- 平台：Flyme、Shizuku、Xposed/HyperOS 相关能力

主要入口类型：

- Activity：`MainActivity`、快捷方式中转、图片选择/分享中转、语音捕获入口、Widget 配置。
- Service：无障碍、悬浮窗、侧边栏、剪贴板监听、快捷磁贴、短信通知监听、日历监听。
- Receiver：闹钟、开机恢复、日程动作、提醒对账、Widget、短信。
- Provider：Shizuku、FileProvider。

维护外部入口时必须同步检查：

1. `AndroidManifest.xml`
2. package/FQCN 是否兼容历史入口
3. ProGuard/R8 规则
4. 通知 PendingIntent、快捷方式、Widget、Worker 是否引用该入口

## 9. 架构护栏

根目录 [build.gradle.kts](build.gradle.kts) 定义了 `checkArchitectureGuardrails`。

当前护栏检查：

- 禁止 UI/Worker 等调用旧 Repository 单例入口。
- 禁止 UI contract 依赖具体 ViewModel。
- 禁止 flavor host 依赖具体业务实现。
- 禁止恢复运行时 `UiStyle` / `miui` 分支。
- 禁止 shared main 业务代码使用 `BuildConfig.UI_EDITION`。
- 禁止新增 `*Center.kt`，当前 baseline 明确为“无 transitional Center”。
- 校验 `native` / `hyperos` host 文件对称。
- 校验设置页和通知类型注册完整。

新增代码时优先修代码，不要随意更新 baseline。

## 10. 维护规则

### 10.1 新增业务功能

推荐落点：

```text
feature/<domain>/
```

如果是系统入口或 Android 副作用：

```text
platform/<capability>/
```

如果是稳定公共契约：

```text
shared/operation
shared/query
shared/event
shared/content
```

如果是纯公共 UI 或工具：

```text
shared/ui
shared/util
```

### 10.2 禁止事项

- 不恢复旧顶层 `core/data/calendar/store/ui/service` 作为源码目录。
- 不新增 `*Center.kt`。
- 不让 UI 直接写 Room。
- 不让 Receiver/Service 绕过 feature application/facade 写业务。
- 不把 flavor 当业务分支。
- 不把敏感签名信息、API Key、用户日志写入仓库。
- 不用 `Set-Content` 批量重写含中文 Kotlin 文件，避免编码破坏。

### 10.3 目录清理

这些属于构建产物/本地缓存，可删除，下一次构建会重新生成：

```text
.gradle/
.kotlin/
build/
app/build/
location/build/
```

这些属于项目本体，不应作为缓存删除：

```text
gradle/
gradlew
gradlew.bat
gradle.properties
settings.gradle.kts
build.gradle.kts
app/build.gradle.kts
location/build.gradle.kts
```

## 11. 当前风险与注意点

- 本次大迁移后工作区改动很大，提交前应重点 review 外部入口 FQCN、Manifest、Worker、Receiver、Widget。
- `native` 和 `hyperos` 目前 UI host 对称，但 HyperOS 风格还未真正完整替换。
- 设置页部分历史 Material renderer 已合并进 main connector，后续做 HyperOS UI 时应再拆分渲染层。
- 旧 `ai-engine` 不在当前构建中，若未来恢复本地模型，需要重新设计模块 include、Manifest、前台服务、R8 和设置入口。
- 天气、随口记、悬浮窗、短信监听高度依赖 ROM 行为，真机验证比单元测试更重要。
- 覆盖安装场景要关注 Room migration、SharedPreferences 兼容和旧数据修复；卸载重装正常不代表升级路径正常。

## 13. 一句话架构总览

```text
输入入口
  -> feature connector / application
  -> shared operation/query/event contract
  -> feature data/domain 或 platform gateway
  -> Room / SharedPreferences / Android Framework
  -> UI / Widget / Notification / Capsule / Backup
```

维护方向：业务继续向 `feature` 收敛，系统副作用继续向 `platform` 收敛，公共契约继续向 `shared` 收敛，应用装配和全局状态保留在 `app`。
