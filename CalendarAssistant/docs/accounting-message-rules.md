# 通知与短信自动记账

## 开启与权限

偏好设置 → 记账 → 自动记账下展开“通知与短信记账”，默认关闭。开启时先检查通知使用权，再申请 READ_SMS / RECEIVE_SMS；全部通过才保存开启状态。取消授权保持关闭。关闭自动记账会一并关闭子开关。运行时及入库前再次检查开关和权限。

通知通过现有 SmsNotificationListenerService 接收，短信通过 SMS_RECEIVED、ContentObserver 及系统短信通知兜底。与取件短信开关独立。广播先拼接分段；Observer 保留取件历史恢复行为，但记账只处理本次监听会话开始后的新短信，不扫描历史账单。

入口 → AccountingMessageCoordinator → RecognitionApi.analyzeAccountingMessage → 本地规则 → 原有账单去重入库 → 原有结果胶囊/通知。未命中静默跳过，没有 AI 兜底，也没有“正在识别”。同一消息重复投递持久化抑制，跨截图、XP、短信等来源继续由现有账单去重规则处理。

## 首批内置格式

| 来源 | 已覆盖格式 | 依据 |
| --- | --- | --- |
| 支付宝通知 | `你有一笔10.73元的支出，点击领0.5元话费券。` | 用户日志中的真实通知；仅抽取支出金额 |
| 支付宝通知 | `你收到一笔9.01元退款，点此查看账单详情！` | 用户日志中的真实通知；退款记收入 |
| 建设银行储蓄卡短信 | 尾号、月日时分、业务说明、支出/收入人民币金额、活期余额 | AutoResource 公开样本；不取卡号或余额 |

规则是按样本独立编写的 Kotlin 命名分组表达式，没有移植参考项目的 JavaScript 执行器或 AI 分析流程。不表示其他银行、所有通知文案已经适配。建行参考：

## 规则编辑

开发者 → 正则规则 → 记账规则，可新增、删除、启停、上移排序；修改后点“保存规则”。恢复默认也需保存后才生效，删除全部规则并保存会停止规则匹配。

- 来源类型为通知或短信，来源正则整串匹配应用包名或短信发件人。
- 正文正则按“标题 + 换行 + 正文”查找，按顺序使用首条有效匹配。
- `amount` 为必填命名分组，人民币金额必须为正数，最多两位小数；支持规范千位分隔。
- `merchant` 可选，缺失时用默认名称；`transactionId` 仅用于真正的支付交易号，不要填卡号或商户订单号。
- `time` 可选，按配置的日期格式解析。无时间时使用消息时间；有时间但无效则跳过。银行短信缺年份时使用不晚于接收时间的最近年份。
- `EXPENSE` 支出、`INCOME` 收入、`TRANSFER` 不计收支。退款必须选收入。
- 测试使用当前编辑内容，不保存规则、不入库、不发结果通知。保存后下一条消息使用新配置；不会回放过去未命中的消息。

## 待 Release 真机验证

1. 两权限都缺、只缺一项、取消授权、全部已授权；都满足才打开子开关。
2. 关闭取件短信功能，仍能独立接收符合规则的财务消息；关闭记账子开关后不再入账。
3. 支付宝支出/退款通知：只显示结果，金额不受营销文本影响；已有截图账单走原有重复提示。
4. 新银行卡短信、长短信、重复通知更新：应只计一次；历史短信不因开启功能自动导入。
5. 开发者修改规则后保存，再接收消息验证即时生效。手机系统隐藏正文或抑制通知时，此路径无法取得内容。

本轮只做 Kotlin 编译、架构守卫及 JVM 测试，未打包 Debug、未装机。
