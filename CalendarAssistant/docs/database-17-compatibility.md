# 数据库 17：记账暂停后的覆盖安装兼容

## 原因

记账测试分支使用数据库版本 16；回到主线后代码恢复为版本 15，缺少 16→15 迁移。覆盖安装时，启动阶段访问 `events.db` 会触发 Room 的迁移缺失异常。

单独把版本改为 16 也不够：相同版本不会触发迁移，而删除记账 Entity 会改变 Room 结构标识。

## 当前方案

- 统一数据库版本为 17。
- `AccountingEntry` 只保留与旧版一致的 19 个字段、主键及两个索引，由 Room 管理表结构。
- 新安装：Room 创建全部表，记账表为空。
- 15→17：只创建 `accounting_entries` 和索引，保留其余表。
- 16→17：不改表、不改数据，由 Room 校验结构并写回版本及结构标识。
- 更早的数据库沿原有迁移链到 15，再升级到 17。
- 不接入记账 DAO、页面、识别、录入或记账同步流程；未启用破坏性迁移。

## 验证

- 已比对保留的 Entity 与记账分支的全部字段类型。
- 已用本地缓存的版本 15/16 Room 建表 SQL 做内存 SQLite 验证：15→17 的建表及索引与 16 一致，12 张原有业务表的样本数据保持不变，记账表为空；16 的 13 张业务表样本数据保留。
- `Database17CompatibilityTest` 使用独立随机命名的测试库，覆盖 15/16→17、笔记/账目保留和第二次打开；不操作真实 `events.db`。
- 当前未执行 Gradle 编译或 Android Room 实机测试；覆盖安装启动结果待验证。
