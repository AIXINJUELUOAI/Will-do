# 自动记账首版联测说明

## 使用入口

偏好设置 → 记账 → 自动记账，默认关闭，说明为“自动捕获支付信息”。这一个开关同时控制无障碍与 Xposed 自动入口。关闭时手动截图、文字识别不受影响；已发出的网络请求无法撤回，但取消后的识别结果不再自动入库。

### 无障碍

- 开启 Will do 无障碍服务，配置可用的多模态模型，再打开自动记账。
- 微信或支付宝出现支付/付款/收款/转账成功页面，且 UI 树可读到成功状态和金额时，页面稳定后自动截图。
- 微信支付统一事件入口：观察到 `UIPageFragmentActivity` 建立候选会话，再收到同一支付窗口事件的“支付成功/付款成功/转账成功”，才允许截图。不再要求先经过好友转账 `RemittanceUI`，使扫码等进入同一承载页的支付路径也能复用。包括实测中的 `TYPE_VIEW_HOVER_ENTER`，不要求事件 source 或 UI 树提供文字。仅进入承载页不能触发；使用其他承载页或不发送成功事件的微信版本仍需另行适配。
- 支付会话最多有效 120 秒，成功信号后等待 700ms，每窗口会话只消费一次；截图前后检查微信前台根节点的包名、窗口 ID、会话和 5 秒信号有效期。后续空树刷新不重置该等待，退出到聊天/历史详情会使会话失效。相同窗口的重复事件不会续期，也不会重新开启已过期或已消费的会话。保留全局互斥、15 秒最短间隔和现有入库去重。
- 仍使用现有多模态模型，没有恢复 OCR。自动截图会产生当前模型的调用费用。
- 单笔详情页按内容就绪触发：同一份可见节点快照或事件文字中，需要有“账单详情”“交易详情”“交易单号”“交易订单号”“转账单号”“商户单号”“商户订单号”等详情标记、可识别金额，以及支付/交易/转账等时间字段和日期时间值。仅标题、点击支付卡片、进度条或“加载中”不会截图；最终交易状态仍由模型确认。
- 支付宝截图中的“账单详情 + 收钱码收款 + 交易成功”允许用“创建时间”作为就绪时间字段，仍须金额和完整日期时间齐全；不放宽普通待支付订单。此适配依据截图，实际无障碍文字仍待 Release 验证。
- 用户选择放开微信收款小账本与支付宝经营分析汇总首页：微信“收款记录 + 今日收款 + 共计”、支付宝“收款概览 + 收款金额 + 收款笔数”组合配合金额及统计日期触发，同样支持事件 source。沿用单笔识别与入库，仅把主收款合计作为一笔收入，不拆笔、不计算差额、不按日更新；备注标明收款汇总。没有时分时按统计日期 00:00:00 记账，原有重复抑制和账单去重保留，汇总与逐笔记录之间可能重叠，由用户自行处理。统一提示词协议 v13 自动替换旧缓存中的 v12 协议，保留自定义正文。
- 详情标记优先于“全部账单”“交易记录”“收支统计”等导航文字；这些词只有在没有详情标记时才按列表信号拦截。聊天页及编辑状态仍优先拦截。事件关键词和截图前后树校验采用同一规则，避免详情页右上角的“全部账单”按钮误阻断。
- 前台根为空时，即时读取事件 `source` 的可见子树并释放节点，再尝试事件 text/contentDescription；不延迟持有 event/source。已核实的微信 `RemittanceDetailUI` 可作为页面身份，但也必须等到金额和时间出现。没有关键内容就跳过，不持续截图或调用模型试探。
- 页面身份按实际前台根的包名和窗口 ID 绑定。后方 LauncherUI 的迟到事件不能覆盖前台详情身份；离开页面使候选失效。聊天页及编辑状态仍排除。
- 内容就绪后才开始 700ms 防抖及 5 秒信号有效期，截图前后再次核验前台窗口。加载十秒不会消耗就绪信号的有效期。同次访问只尝试一次，局部 source 仅含导航按钮时不会重开会话；就绪内容只保留摘要用于五分钟重复抑制，避免空根退回单纯按窗口排重。全局 15 秒最短请求间隔继续有效。
- 详情及汇总识别只接受单笔、无解析异常且状态完成、有有效记账时间的账单；普通详情必须使用真实交易时间，汇总使用上述统计日期约定。不满足则暂不入库，历史账单不会回填当前时间。通过后仍走已有账单去重，不创建日程。支付现场缺时间的原规则保留。
- 历史账单列表、聊天输入页不自动识别；未支付、失败或取消的交易不入库。无法获取信号的详情页仍可由用户主动识别。
- 每次识别完成后才允许下一次，另有最短请求间隔和重复页面抑制；频繁刷新成功页不会持续发送同一内容。
- 自动结果只处理账单，不创建日程。识别到账单后，将图片独立保存到应用私有的 accounting_images 目录，入库与待确认草稿均保留关联；明确重复且没有新增或待确认记录时移除本次图片。

## 本轮记账交互回归

- 自动截图成功并通过页面校验后，沿用现有进度通知/胶囊显示“正在识别账单”；结束或取消时清理进度，记账结果继续使用现有结果弹窗/胶囊。无账单的空结果不弹成功提示。
- 新建账单默认支出、当前日期时间；每行四个分类按钮，切换收入显示收入分类。首次展开聚焦金额并弹出数字键盘，分类切换不清空金额。更多默认收起，名称未填写时使用分类。
- 键盘打开及大字体下，金额和保存按钮仍可见；分类和更多信息可滚动。无有效金额不能保存；编辑已有账单保留原字段。
- 有/无账单切换时顶部摘要区域保持相同行数，周期标题无切换动画；侧滑后金额与操作按钮有间距。
- 待确认列表操作靠右，底部按钮主题色填充。疑似重复点击“仍然计入”直接保存且移出草稿；重复点击不能多次入库，完全一致的交易号仍拦截。
- 图片识别生成的账单，在详情、编辑和待确认 Sheet 下方可以查看截图；确认草稿、编辑名称后仍保留截图。旧账单没有保存原图的不会补造图片。
- 记账页长按悬浮按钮为“导出 | 导入”，备份页有相同入口。JSON 保存全部已保存账单及其截图，不含待确认识别草稿；重复恢复不覆盖现有记录、不复活已删除记录，不重复留下图片。文件大小沿用账单文件限制，超限提示失败，不生成成功提示。
- 数据库升级到 20，仅在账单和草稿表添加可空 sourceImagePath 列；已有交易与日程均保留。已补升级测试源码，实际设备执行仍需测试机。

### Xposed / LSPosed

- 更新模块后，作用域勾选微信 `com.tencent.mm`、支付宝 `com.eg.android.AlipayGphone`；原 SystemUI 作用域用于超级岛。
- 重新启动对应支付应用，使 Hook 生效；Will do 内仍需开启自动记账。
- 微信主进程观察两种 WCDB 适配器的插入及完整字段更新：`message` 支付服务消息（`318767153`）、专用转账消息（`419430449`）；`AppMessage` 仅接受带支付模板和原始发布时间的 XML。部分字段更新不反查聊天数据库，普通聊天与不含金额的红包卡片不转发。
- 微信主进程及 `:tools` / `:toolsmp` 网页进程观察 `com.tencent.xweb.WebView.evaluateJavascript` 的 `nativeWXPayCgiTunnel:ok` 账单响应；不注入 JavaScript，不修改原始参数或返回值，不转发服务跳转签名。
- 红包领取回调按模型包名和 `onGYNetEnd(int,String,JSONObject)` 签名定位，处理混淆类名；观察后续类加载，并在后台扫描已加载 dex 的候选，最多 512 类。不新增 DexKit 依赖。只有本人 `receiveId` 对应的完成记录、实际领取金额与到账时间均齐全才记收入，金额单位为分；不取红包总额、他人领取金额或上次支付缓存。
- 支付宝继续观察 `SyncMessage.getData`，`toString` 为兼容入口；按结构化 status、money/unit 和 content 字段对解析，不用商品说明、支付方式、累计收款额判断本笔交易。缺少完整时间且没有可信消息时间时跳过，只有“几月几日”不能补造当前时刻。
- 下表表示已实现的协议分支，**不表示真机已验证**。此入口全部本地解析，不调用 AI。

| 场景 | 本轮 XP 处理 |
| --- | --- |
| 微信付款码、扫码及第三方微信支付凭证 | 提取付款金额、模板状态、商家显示名称及交易号；前提是产生已适配的支付服务消息 |
| 微信个人码收款 | 只取本笔收款金额；忽略“今日第几笔/共计”，缺少顾客名称时使用“微信收款” |
| 微信好友转账发出 | `isSend=1 / paysubtype=1` 记支出，使用发起时间与 transferid |
| 微信好友转账领取 | 本人发出的收款确认 `isSend=1 / paysubtype=3` 记收入；使用领取/确认消息时间，未领取不入账 |
| 微信单笔历史详情 | 有符号金额、明确完成状态、交易号及真实时间齐全时补录，沿用原时间及统一去重 |
| 微信本人领取红包 | 只取本人已存入零钱的领取记录，自己发出的红包不作为收入 |
| 微信商家退款 | 到账通知中的退款金额记独立收入，不冲销原支出；不拿原付款单号当退款单号 |
| 支付宝付款、自动扣款、转账、码收款 | 兼容相应完成状态，余额宝付款方式、充值商品说明不再误阻断普通消费 |
| 支付宝到账退款 | 明确到账状态才记收入；独立 `_M` 退款号可用于去重，普通原交易号不作退款身份 |

- 消息及红包响应仍只接受最近十分钟数据；**仅明确打开的详情响应**允许历史时间，未来时间及缺失时间拒绝。不同入口共用账单去重。转账消息不读取联系人库，缺少显示名称时使用“微信转账”，备注注明。
- 仍未覆盖：发红包（公开消息缺实际金额，未采用上游松散金额缓存）、群收款系统聊天消息、理财/提现/本人账户互转，以及支付宝详情页 JS 注入方案。微信原生转账网络模型的专用回调也未单独移植，当前转账走数据库确认消息及详情桥接。未知结构可用主动识别补录。
- 没有自动记录不代表交易失败；Hook 安装、版本字段匹配和实际记录需要分别验证。
- Hook 类名、方法与消息结构可能随微信/支付宝版本变化。当前实现依据公开源码，尚未在真机确认兼容版本。

## 建议分开验收

1. 开关关闭：正常使用支付 App，不应自动截图、请求模型或新增账单；手动识别仍正常。
2. 单测无障碍入口：暂不启用支付应用 Xposed 作用域，停留在一次正常支付的成功页，检查金额与实际新增笔数。
3. 刷新/反复停留同一成功页，观察模型请求不应重复；识别中关闭开关，检查晚返回结果不入库。
4. 单测 Xposed 入口：关闭无障碍服务，开启支付应用作用域并重启应用，检查新支付消息能否产生记录，模型用量应无新增。
5. 两条入口同时开启：同一交易只应入账一次；另一条触发时提示重复或疑似重复。
6. 失败、取消、收款方尚未领取的转账、历史账单列表不应自动记账；付款方明确支付成功但等待对方收款的转账按支出处理。两笔明确不同交易号的真实交易不能被直接合并。
7. 保留一次主动截图与取消测试，确认原有日程/账单识别仍正常。
8. 打开单笔历史详情，核对账本保存的是实际交易时间；缺时间、返回多笔或状态不明时不应入库。重复刷新详情页不能连续请求模型。
9. 聊天里发送“账单详情/交易单号”、进入账单列表、截图前离开详情或关闭开关，均不应入账。微信无任何详情信号时按约定跳过。

## 反馈信息

记录手机系统、微信/支付宝版本、LSPosed 版本、开启的是哪条入口、支付场景与实际表现。App 使用现有日志导出入口，重点看 `WillDoAccounting` / `WillDoRecognition`；LSPosed 日志搜索 `WillDoAccounting`。

- `wechat installed` / `alipay installed`：Hook 方法已注册，不代表实际交易已捕获。
- `wechat ... insert/update installed`、`wechat detail installed`、`wechat red_packet hook=...` 分别表示数据库写入、详情桥接、红包模型回调已注册；`red_packet scan completed candidates=...` 仅是候选扫描结果。各入口安装失败互不阻塞。
- `unavailable`：Hook 点不匹配或跨进程接口不可用。
- `capture=processed`：已走入库处理，可能新增、重复或待核对；以岛上结果为准。
- `capture=unmatched`：消息格式、完成状态或时间未满足本地规则，没有调用模型兜底。
- `failed`：本地处理异常，可结合 App 日志定位。

`WillDoAccounting` 诊断日志只输出判断结果，不记录 UI 树原文、交易对方、金额或单号。临时的全局 UI 树日志采集已移除。

### 自动触发阶段日志

应用日志搜索 `WillDoAccounting`，无障碍记录包含 `stage`，高频事件按阶段与来源限流为最多每 5 秒一条，不代表每次窗口刷新：

- `service` / `settings`：服务连接状态、自动记账开关及模型配置是否齐全。
- `event`：收到支付应用窗口事件；`debounce_cancel` 表示 UI 树路径的原等待被新的支付应用事件取消，其他应用事件不重置等待。
- `success_event`：微信支付会话捕获成功事件，只记录事件类型、窗口 ID 和会话编号，不打印文字、金额或联系人。`success_event_ready` 表示等待后会话校验结果。
- `detail_content`：事件源的详情标记、金额、时间、加载状态及是否就绪，只输出布尔判断。`detail_signal`：内容就绪候选，`evidence` 为 `event_source`、`tree_text`、`event_text` 或 `known_page`；`detail_ready` 及截图前后的 `route=detail` 记录会话/前台校验结果，不打印页面原文。`reservation route=detail` 沿用请求间隔和重复抑制。
- `gate`：正在识别、配置缺失或开关关闭等入口拦截。
- `screen`：`success` / `amount` 表示 UI 树文字是否匹配成功状态/金额；`editable` 表示发现编辑框；`excluded` 为命中的固定排除词，`eligible` 为综合结果。这些判断不代表模型已看过截图。
- `reservation`：`ACCEPTED` 放行，`REPEATED_PAGE` 为重复页面，`MIN_INTERVAL` 为请求间隔未到。
- `before_screenshot` / `after_screenshot`：UI 树路径检查页面条件与内容指纹；`route=success_event` 的微信事件路径检查前台窗口和会话有效性，不要求空树匹配成功文字。
- `screenshot`：已请求、成功或失败及系统错误码；`result`：识别结果和对应 `trace`；`finish`：异常/取消/超时；`task_end`：自动任务结束并释放占用。

可通过阶段日志确定拦截位置。仅凭 `success=false` 不能断言成功提示是图片，也可能是节点文字与现有词表不匹配。
