## 六、MIUI 组件实验与全局毛玻璃

### 6.1 MIUI 组件实验页

开发者页新增 MIUI 风格实验入口，用于集中验证：

- 卡片。
- 开关和滑块。
- 对话框。
- 下拉菜单。
- 底栏和浮动按钮。
- HyperCeiler 风格布局参考。

初期尝试直接引入 `fan.miuix`，但其 GitHub Packages 认证、依赖体积和 Native flavor 无需携带该库的问题增加了维护成本，因此撤回该方案。

最终决策：

- 以 `top.yukonga.miuix.kmp` 为主要组件库。
- HyperCeiler 只作为布局、间距和缺失组件的视觉参考。
- Native 不引入完整 MIUIX UI/Preference 组件，只共享必要的 blur 后端。

### 6.2 早期毛玻璃方案及失败原因

第一版通过复制壁纸位图、计算卡片在根布局中的偏移，再对复制图层应用 `BlurEffect`：

- 静止时可以看到模糊。
- 滚动后容易出现模糊区域只覆盖卡片上半部分。
- 卡片移动时采样坐标不能稳定追随。
- 浮层只能看到壁纸，无法看到后方日期卡片或页面内容。

随后尝试“先把整张壁纸模糊，再让卡片透明显示”的兼容方案，但这只是模糊背景图片，并不是卡片材质，最终被否决。

### 6.3 MIUIX 实时模糊材质

最终统一使用 MIUIX blur：

- 通过 `LayerBackdrop` 采集真实后方场景。
- 通过 `textureBlur` 生成卡片材质。
- Native 和 HyperOS 使用同一模糊后端。
- MIUI 模糊作为独立材质开关，不受标准卡片透明度影响。
- 标准卡片材质继续使用透明度配置，两种材质互斥。
- 使用壁纸背景时，MIUI 模糊默认开启。

### 6.4 浮层采样层级

为解决 Dialog、Sheet 和 FloatingActionCard 只模糊壁纸的问题，增加浮层专用采样：

- 页面级卡片采样主背景 `backdrop`。
- Dialog、Sheet、菜单和浮动操作卡采样当前页面渲染结果 `overlayBackdrop`。
- 浮层内部继续发布新的 backdrop，支持后续子弹窗叠加。
- 模糊本身承担层级区分后，降低或移除不必要的背景压暗。
- 修复 Sheet 采样错误、背景层错位和模糊层级不连续。

### 6.5 视觉收口

- MIUI 模糊开启时移除卡片外围描边。
- 移除主页日期卡、底栏、随口记详情工具栏的描边。
- 新增/编辑日程、课程、滚轮选择器、Dialog 和 Sheet 逐步接入模糊材质。
- 系统底部手势小白条所在区域由系统窗口管理，应用模糊无法覆盖，确认为平台边界。

## 八、短信取件码识别与去重

### 8.1 短信监听排查

用户反馈短信取件码无法入库且没有日志，排查范围包括：

- `SmsReceiver`。
- `SmsContentObserver`。
- `SmsNotificationListenerService`。
- `SmsPickupIngestCoordinator`。
- 日程入库去重。
- 参考项目 `parcel-main.zip` 的短信读取策略。

增强内容：

- ContentObserver 查询和日志。
- 通知监听短信文本提取。
- 京东等取件短信格式匹配。
- 短信来源入库链路诊断。
- 对应短信分析测试。

最终真机确认：小米“5G 消息/RCS”不会进入传统 SMS 数据库；关闭 5G 消息后，同一短信可以正常入库。这一平台限制无法仅靠传统短信权限解决。

### 8.2 可配置去重

开发者页新增短信取件码去重开关：

```kotlin
smsPickupDedupEnabled: Boolean = true
```

- 默认开启，保持现有安全行为。
- 开启时相同短信取件码只入库一次。
- 关闭时短信来源跳过既有事件去重检查。
- 设置同时进入 `ConfigCatalog` 和入库链路。

## 十、HyperOS flavor 全面重写

### 10.1 设计基线

本轮明确不再把 HyperOS 做成“原生 Material 页面换一套颜色”，而是：

- 使用 MIUIX 默认 HyperOS 色彩，不跟随应用自定义主题色。
- 一级页面使用紧凑 TopBar，标题位于左侧，操作位于右侧。
- 一级页面名称统一为“今日、全部、随口记、设置”。
- 底部使用默认 NavigationBar，不再使用原生悬浮底栏方案。
- 设置页改为底栏一级页面，承接原抽拉式设置侧边栏。
- 新建按钮位于底栏外侧右方，点击直接打开新增日程。
- HyperOS 图标优先使用 MIUIX Icons，不混用不同风格图标。

- Card、Dialog、Sheet。

- 修复打开菜单或搜索时闪退。

## 十三、列车与航班自动状态切换

偏好设置新增：

```text
列车与航班信息自动切换
```

配置：

```kotlin
transitAutoCheckInEnabled: Boolean = false
transitAutoCheckInMinutes: Int = 15
```

- 默认关闭。
- 提供 `10 / 15 / 30 分钟`三档离散滑块。
- 列车在发车前到达阈值后真实调用现有 `checkInItem()`，写入“已检票”。
- 航班使用同一业务接口，按现有规则写入并展示“已登机”。
- 状态切换后胶囊展示车次/航班和座位信息。
- 普通事件和重复事件实例均携带正确 `ActionTarget`。
- 胶囊提前显示时间会覆盖自动切换阈值，避免状态已经变化但胶囊尚未出现。
- 使用线程安全 in-flight 集合防止 10 秒 ticker 重复提交，失败时保留重试机会。
- 补充 `EventTags.FLIGHT` 到胶囊规则回退。

该功能当前已经完成静态链路检查，但尚未进行最新工作区编译和真机到点触发验证。
