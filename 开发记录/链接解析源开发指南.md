# 解析源开发入门：从博客示例开始

应用提供链接收藏、受控请求、素材处理、在线 AI 摘要、保存和通知。源只负责把一个链接转成约定的数据：标题、正文、图片／音轨地址等。公开教学材料包括作者自有博客的示例、协议样例和离线校验工具，不包含私人平台源。

你可以直接导入博客示例体验功能，也可以据此为自己有权访问的站点编写源。博客示例的正文提取和手机端摘要生成已于 2026-10-09 得到用户验证；此记录没有把通知点击跳转算作已验证。

## 1. 先用已有示例体验完整流程

[博客示例说明与源码](../examples/link-sources/willdo-blog/README.md) 中包含 manifest、带注释的 main.js 和打包工具。在仓库根目录执行：

~~~powershell
python examples/link-sources/willdo-blog/package.py
python scripts/check_link_source.py package build/link-source-examples/willdo.blog-example-v0.1.0.zip
~~~

把 ZIP 传到手机，在实验室的“导入源”中选择它，收藏 [will do 操作手册](https://aixinjueluoonline.top/posts/will-do-manual/)，然后开启自动摘要或从详情页手动生成。**导入会替换当前源，请保留原 ZIP 方便恢复。** 导入源不用重新编译应用；需要配置现有在线 AI 才能生成摘要。

发布时可以把这个 ZIP 作为 GitHub Release 附件提供，源码保留在 examples 中。生成文件位于 build，默认不进入 Git；教程、源码、样例和校验工具可以一起进仓库。

## 2. 读懂源包和权限

可导入 ZIP 根目录只能包含 manifest.json 和 JS 模块，不包含 README、Python、测试 JSON 或下载的文章。

| manifest 字段 | 含义 |
| --- | --- |
| protocolVersion | 当前协议为 1 |
| id / name / version | 源的固定标识、显示名称和发布版本；更新时增加 version |
| entry | 导出 extract 的 JS 模块，默认 main.js |
| matches | 哪些链接交给此源处理：host 和 pathPrefix |
| permissions.networkHosts | 允许请求的域名；正文、跳转和素材域名都需按需声明 |
| permissions.browser | 是否需要 WebView；普通 HTML 示例为 false |
| permissions.replay | 可选网页请求重放模式，默认空；普通 HTML 示例不需要 |
| loginEntries | 可选的用户登录入口；需要 browser、HTTPS 与对应域名权限 |

matches 用于选择源，networkHosts 用于限制网络访问。精确域名不会授权它的子域；`*.example.com` 只授权子域，不包括根域。博客发布包只有 `aixinjueluoonline.top` 这一个域名，没有通配符。

JSON 清单不能加入注释或自定义 note 字段。修改目标站点时，同时检查链接匹配、网络权限和脚本中的目标／正文判断。未修改的博客包只访问这个博客，修改后的源由开发者自行确认访问和使用权限。

## 3. 源脚本拿到什么、应该返回什么

入口固定为 `export async function extract(input, host)`。QuickJS 不是 Node.js 或网页：不能直接使用 fs、require、Buffer、process、fetch、DOMParser 或浏览器 URL 对象。博客示例用 host.http.request 获取 HTML，再提取正文。

input 包含 protocolVersion、requestId、url 和可选 shareText。示例只使用请求 ID 和链接，不依赖 shareText；不向源提供应用数据库、AI Key、Shell 或任意文件访问。

| 返回字段 | 应怎样填写 |
| --- | --- |
| protocolVersion | 当前为 1 |
| requestId | 原样返回 input.requestId，不能换成内容 ID 或随口记 ID |
| status | ok、partial 或 error，依据实际取得的内容 |
| source.url | 成功／部分成功时逐字返回 input.url，保留 query 和 fragment |
| source.canonicalUrl | 页面标准或最终地址，不能拿它替换 source.url |
| source.contentId | 可选的文章／素材 ID，用于描述来源 |
| title / author | 从实际内容取得；没有作者可以为空 |
| contentType | article、image_post、video、mixed、unknown |
| body.kind | full 是完整文字正文；excerpt 是节选；description 是简介；none 是没有文字 |
| body.format / text | format 只能为 plain；text 为目标内容文字，去掉导航／侧栏／页脚 |
| media | 有顺序和角色的素材地址；无素材时使用空数组 |
| warnings | 实际缺失或限制的简短说明，不用重复堆叠 |
| error.code / message | error 时给出固定错误码与简短说明；宿主按 code 显示固定文案 |

JSON 结果也不接受额外字段，注释放在 JS 或文档里。

ok 表示取得了本次源声明的目标内容。只有节选或简介、缺少完整目标内容时使用 partial，并说明范围。warnings 也可以随 ok 返回：例如博客示例取得完整文字，但没有下载文中的图片，会明确说明“仅提取文字”。

视频已有完整音轨时，正文仍可能只是 description，这不必单凭 body.kind 就把整个结果判成 partial。只有标题、封面或 BGM 时，不能声称已经取得完整视频内容。页面拿不到时明确失败，不能用推荐内容、导航或分享套话冒充正文。

## 4. 六个离线返回案例

[protocol-cases.json](../examples/link-sources/protocol-cases.json) 包含可直接检查的输入／输出配对。URL 均是占位值，工具不会访问它们：

| case.name | 演示 |
| --- | --- |
| ok_text | 完整文字正文，status=ok、body.kind=full |
| partial_excerpt | 仅取得节选，status=partial，带范围说明 |
| no_article | 没找到正文，error.code=NO_ARTICLE |
| access_required | 需要登录或验证，error.code=ACCESS_REQUIRED |
| http_too_large | 响应超过宿主上限，error.code=HTTP_TOO_LARGE |
| mixed_media | 混合素材格式，包含正文图片、封面、完整音轨、BGM 与视频 |

模拟错误用来说明协议，博客示例不会主动制造登录或超限场景。HTTP_TOO_LARGE 对应宿主当前的 8 MiB 文本响应上限；不能截断响应后仍标为 full。需要登录／验证时保留失败状态，用户可以完成交互后重试。

### 图片、音轨、封面如何区分

| media.type | media.role | 用途 |
| --- | --- | --- |
| image | content_image | 正文图片，作为内容素材 |
| image | cover | 封面，不能证明正文完整 |
| audio | speech_audio | 完整语音／旁白音轨，供本地转写或在线模型处理 |
| audio | background_music | 背景音乐，不作为视频完整旁白 |
| video | video | 同一目标视频，可供宿主提取内嵌音轨 |

order 在整个结果中唯一。group 关联同一目标视频的音轨、视频和封面，不同视频分组。urls 是同一个素材的备选地址，不是多张图片的集合。音轨与视频时长接近只是判断线索，不证明音轨含有完整旁白。

源只返回 HTTP(S) 地址及必要请求头，不把素材 Base64 或本机路径放进结果。图片／音频的真实格式、下载、解码、AI、入库和通知由宿主完成。mixed_media 仅演示这些角色，不建议实际每次都同时返回所有角色。

## 5. 用离线工具检查自己的输出

[check_link_source.py](../scripts/check_link_source.py) 需要 Python 3.9 或以上，仅使用标准库，不需要 Android SDK 或安装第三方依赖。它不联网、不执行 JS、不运行浏览器、不调用 AI。

在仓库根目录执行：

~~~powershell
# 检查 ZIP 条目、UTF-8、清单字段、权限与体积
python scripts/check_link_source.py package path/to/my-source.zip

# 检查你在开发环境保存的 extract 输出及其原始 input
python scripts/check_link_source.py result path/to/result.json --input path/to/input.json

# 检查仓库中的完整教学案例
python scripts/check_link_source.py examples examples/link-sources/protocol-cases.json

# 检查工具自身的正例、反例和 ZIP 路径边界
python scripts/check_link_source.py self-test
~~~

成功显示 PASS，失败显示固定字段／规则提示并以退出码 1 结束，不打印正文、凭据或完整链接。工具检查常见协议错误：未知字段、类型、枚举、任务 ID／原链接、正文上限、素材序号与地址、登录权限，以及 ZIP 路径／大小。

这是开发预检查，不代替 App 的最终校验：工具不会验证 JS 语法和模块导入、真实 DNS／跳转／登录、请求头是否适合目标站点、素材是否可下载或 AI 是否支持。它还要求错误结果有明确 error 对象、成功结果不携带 error、durationMs 非负；这些是教程推荐的明确输出方式。运行时与资源边界以 [完整协议](链接解析源接口协议.md)、LinkSourceProtocol、LinkScriptRuntime 和 ConfigCatalog 为准。

## 6. 不熟悉 JavaScript 时，如何借助编程 AI

可以把本指南、完整协议和博客示例一起交给你使用的编程 AI，再提供你有权访问的网页结构。下面是一个任务模板：

> 请按 Will do 源协议 v1，为【我有权访问的 HTTPS 站点】写一个可导入的源。
> 使用博客示例的 manifest.json + main.js 结构，网络权限仅声明【所需精确域名】。
> 页面正文在【我提供的 HTML 容器】，标题／作者在【相应字段】。
> 入口是 export async function extract(input, host)，通过 host.http.request 请求；QuickJS 中没有 Node.js 和浏览器全局对象。
> 第一版只提取完整标题和文字正文，不取图片或音频，不申请浏览器、登录和重放权限。
> requestId、source.url 原样保留，不增加协议外字段。
> 找不到当前目标正文时返回明确错误；不把整个页面或其他内容作为完整正文兜底。
> 请写清字段注释，提供 input/result 样例，并告诉我怎样按协议文档检查与打包。

AI 生成的代码仍需要校验、导入和手机验证。页面需要动态渲染时再参照完整协议的 browser 能力；能力不足时明确报错。先完成一条自有页面的文字摘要，再逐步增加图片和音频。

## 7. 手机上验收哪些结果

1. 导入后名称和版本正确，收藏的链接能匹配当前源。
2. 提取内容对应当前文章，含正文末尾，排除导航与推荐内容。
3. 摘要回写原随口记，范围说明如实显示，失败后仍保留原链接。
4. 完成通知打开对应详情；取消和失败不出现成功通知。
5. 更换／删除源后旧任务不能写回；再次导入更新包后手动重试已有记录。

本教程帮助源作者理解和验证接口；它不提供源市场、私人平台源下载或自动平台适配。更多宿主能力与错误码见 [完整协议](链接解析源接口协议.md)。
