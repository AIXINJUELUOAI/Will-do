## 1. 随口记支持多个提醒

- 随口记详情页增加提醒区域，可为同一条随口记新增、修改、删除多个提醒。
- 提醒具有独立 ID、触发时间和重复规则，不再仅依赖随口记上的单个提醒字段。
- 当前随口记重复提醒接受每日、每周规则；不接受按次数结束的规则。共用重复计算工具具备更广的频率支持，不代表随口记界面已开放全部频率。
- 增加提醒调度器和广播接收器；具备精确闹钟权限时使用精确调度，否则回退到非精确闹钟。
- 提醒通知展示随口记正文；没有文字时使用图片、语音或查看提示。点击通知进入对应随口记。
- 单次提醒触发后移除该提醒，重复提醒计算下一次时间并继续调度；删除随口记时取消相关闹钟。
- 增加启动、设备重启后的提醒重排逻辑。重排时已过期的单次提醒会被移除，重复提醒推进至下一次，不将其描述为历史提醒补发。
- 上述为阶段初版行为；9 月 13 日实测后已修正为先补发过期提醒，只有实际发布成功才删除单次提醒或推进重复提醒，最终行为见第 7 节。

主要代码：`QuickMemoFacade`、`QuickMemoReminderScheduler`、`QuickMemoReminderReceiver`、`QuickMemoReminderSection`。

## 3. 重复日程实例附件与暂存附件修正

- Agent 附件接口增加实例时间参数，支持将附件绑定到指定重复实例，而不是默认挂到整个系列。
- 第一次为未物化实例添加附件时创建独立子事件，并返回真实子事件 ID；查询附件不创建子事件。
- 对已排除、不存在或时间不匹配的实例执行校验，避免附件错误归属或重新创建被删除实例。
- 日程编辑对话框的暂存附件键改为独立 `pending:` UUID，避免暂存键与真实事件指纹相同，导致母事件提前认领实例附件。
- 关闭编辑对话框时，按所有未绑定附件的暂存键清理，不再只处理新建场景中的第一个键。
- 附件绑定和重复实例解析的接口说明、调用示例与边界详见文末合并的 9 月 9 日记录。

## 6. 自动日志统一与三天滚动保留（9 月 13 日）

本次检查发现原链路存在三个主要问题：普通日志只保存当天且超限清空；异常日志仍优先写 Download；大量业务日志只调用系统 Log，导出时才临时补抓 Logcat。另外，异常日志写入私有目录备用文件后，旧导出逻辑没有读取这份备用文件。

本轮调整：

- 应用自身的运行、识别、同步、通知、异常和卡顿等日志接入 `AppLogger`，按日期写入私有目录 `files/diagnostics/`。
- 文件名采用 `log-YYYY-MM-DD.log`；同一天追加同一个文件，不按业务类别拆分。
- 保留今天及前两个自然日。例如 9 月 13 日保留 11、12、13 日，删除 10 日及更早记录。
- 在启动、写入及读取导出日志时清理过期文件，不设置午夜唤醒任务；应用未运行期间不会主动执行清理。
- 每日日志上限为 4 MB，达到上限后停止当天追加，保留已记录内容，下一天继续写新文件。
- 使用线程同步和文件锁保护读写；子进程通过共享的关闭标记读取记录开关。
- 原异常记录入口转入统一日志，避免继续在 Download 创建独立异常文件。
- 增加旧私有日志和可读取的 Download 自动日志迁移，包括重名副本枚举。旧文件在合并成功后删除；读写、删除失败或合并超出容量时，不能保证旧文件已经全部移除。
- 系统 Logcat 继续用于即时调试，Xposed/SystemUI 侧传输日志不视为应用私有日文件；用户主动导出时仍可附带当时可读取的 Logcat。

### Agent 重复实例附件 API

`addEventAttachment` 和 `listEventAttachments` 新增可选参数 `occurrenceTs`，单位为 Unix 秒，与重复日程操作一致。

示例 payload（具体时间取 `queryEvents` 返回的实例 `startTs`）：

```json
{
  "eventId": 123,
  "occurrenceTs": 1788944400,
  "file": { "contentUri": "content://your.provider/document/456" }
}
```

- `eventId` 为重复母事件 ID 时，添加必须提供 `occurrenceTs`，否则返回参数错误，避免静默绑定整个系列。
- 首次添加会将该次实例物化为独立子事件，并返回真实子事件 `eventId`。继续添加可使用返回的 ID，也可继续使用母事件 ID 与该次开始时间。
- 实例已经改过时间时，使用查询返回的子事件 ID；被排除或不存在的实例不会被重新创建。
- 查询指定实例不会物化数据。没有独立子事件时返回空列表；不传 `occurrenceTs` 则按 `eventId` 查询（母事件 ID 查询系列附件）。
- 单次事件和已有子事件可继续只传 `eventId`；如果同时传开始时间，必须与该记录相符。
- 删除仍使用 `deleteEventAttachment(attachmentId)`，唯一附件 ID 已能准确定位。
- 系列级添加或替换可显式使用 `editRecurringEvent` 的 `mode=ALL` 和 `event.attachments`。`replaceAttachments=false` 追加，`true` 才删除旧附件。
- `getCapabilities` 新增 `supportsOccurrenceAttachments`。文件能力仍只对官方 ContentProvider 通道开放，第三方广播限制保持原有语义。
- `F:/Awill` 调用端的 `willdo_event_attachment` 工具同步增加 `occurrence` 参数，并转换为 `occurrenceTs` 发送。联调需同时安装 Willdo 与 Awill 的新构建。

增加了实例定位回归测试；本轮按用户要求不运行 Gradle 构建或测试，由用户打包验证。
