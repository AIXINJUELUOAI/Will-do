## 1. 最终产品目标与入口

目标流程为：用户复制／分享链接 → 用户确认收藏 → 保存随口记 → 手机提取链接内容 → 已配置的在线 AI 分析 → 保存摘要与允许更新的标题 → 通知直达原随口记。

这条流程以用户主动提供的链接为入口。此前关于跨应用无感获取当前内容原链接的探针方案已结束，本次不依赖常驻识屏、自动点击其他应用的分享菜单或系统日志取链接。

- 系统文字分享和选中文字分享可保存到随口记；有 HTTP(S) 链接时按链接收藏处理，其他文字保存原文。
- 普通权限只在应用窗口获焦时检查剪贴板；Root/Shizuku 授权后使用既有特权读取与监听。系统分享入口不依赖 Root/Shizuku。
- “剪贴板链接收藏”与“自动生成摘要”分开控制，默认关闭。只收藏链接不需要解析源，也不需要先调用 AI。
- 用户决定内容何时入库；未点击收藏的剪贴板提示不会自动新增随口记。

## 2. 链接识别、标题与保存

### 2.1 本地识别规则表

[QuickMemoLinkRules.kt](../app/src/main/java/com/antgskds/calendarassistant/feature/quickmemo/domain/QuickMemoLinkRules.kt) 集中维护来源名称、完整域名、分享套话清理及可选的稳定内容 ID 去重规则。解析器不联网，不通过网址中的任意子串判断平台。

目前名称覆盖抖音、哔哩哔哩、公众号、酷安、小黑盒、小红书、贴吧、知乎、微博；未登记的 HTTP(S) 网址仍以通用“链接”收藏。普通百度网址不自动等同于贴吧，`t.cn` 等目标不明确的短链不直接标为微博。

这里有两种独立的扩展：新增外部解析源的域名和处理模块，可以让内容提取工作；修改 App 的平台名称通知，则需要更新 Kotlin 规则表并重新构建。导入源不会自动修改应用的通知平台名称。

### 2.2 链接记录

- 默认标题为对应的“平台收藏”，小红书同样使用“小红书收藏”；用户可自行编辑标题。
- 有分享文案时正文先放清理后的文案，再换行放完整原链接；纯链接则只保存链接。
- 保留分享查询参数、路径大小写与片段，避免清理 URL 后破坏访问凭证或内容定位。
- 已确认稳定 ID 的酷安 feed 去重按内容 ID 处理；其他未验证稳定性的链接保持保守去重。短链是否指向同一内容不能离线推断。
- 系统分享与剪贴板收藏汇入相同创建入口，事务去重与任务防重分别处理。
- 重新分享可更新未完成收藏的有效访问参数；成功摘要不会因普通重复收藏自动再调用 AI，用户需要时手动重新生成。

## 3. 普通／实况通知与重新复制

- 链接提示胶囊使用“抖音链接”“小红书链接”“贴吧链接”等短文案，通用网址显示“发现链接”。展开标题保留“识别到平台链接”。
- “收藏”动作直接保存当前候选，不必跳回应用；动作只携带稳定提示键，不在点击时重读已经可能变化的剪贴板。
- 保存成功后更新为“已收藏”，保留完整收藏结果和“查看”动作；点击通知或查看进入真实随口记详情。
- 取件类提示显示“识别到取件码|码”等，提供“添加取件／添加取餐／添加取票／添加寄件”的直接入库动作。
- “检测到链接”和“摘要已生成”通知各持续一分钟，普通与实况共用策略；取件类提示不套用这项一分钟调整。
- 相同链接或码重新复制后可以再次提示；同一次复制的重复回调、前台检查或普通重读继续去重。系统无法提供复制时间时使用保守回退，不制造新的复制动作。
- 提示去重与真实入库去重分开；保存失败、关闭提示或提示到期不会永久阻止下一次复制。已经成功收藏的当前链接仍沿用入库去重。
- 全部业务通知通过统一 NotificationApi 链路。只有实际 `POSTED` 才视为投递成功，失败时已保存的记录或摘要保留。

## 4. 文件夹、列表与多选

### 4.1 单层文件夹

- 一条随口记最多归属一个文件夹，不支持嵌套；可以浏览全部、未分组或某个文件夹。
- 常态页面不在 TopBar 下重复增加“全部随口记”一行。右上角三点菜单复用公共 AppDropdownMenu，浏览入口与新建／管理操作之间增加分割线。
- “全部随口记”使用 Topic 图标，文件夹固定使用 Folder；当前只编辑右侧名称，不加入自选 icon、emoji 或图片。
- 新建、移动、重命名使用公共 sheet；移动期间可以创建新文件夹，再返回选择，不叠加两个 sheet。
- 管理文件夹提供重命名与删除，不再添加独立关闭按钮；点外部或返回即可关闭。名称拒绝空白与重复，重命名保留文件夹 ID、创建时间和内容归属。
- 删除文件夹只使其中记录回到未分组，保留正文、附件、提醒和待办。

### 4.2 多选与删除

- 长按条目进入多选，并默认选中所长按的条目；不再触发旧详情浮动操作卡。
- 选择框统一在右侧，选择时隐藏语音播放按钮，不额外加选中高亮外框。
- 底部复用单行胶囊工具栏，仅保留全选、移动、删除。全选仍可取消全选，不显示已选数量或独立取消按钮，返回退出选择。
- 全选采用官方 Done All 图标，工具栏删除为默认配色；最终确认动作仍使用警示色。
- 随口记单条及批量删除的二次确认使用日程同款浮动通知卡，替代早期删除 sheet 的决定；文件夹删除保留自己的确认流程。
- 来源日历、备份内容等同类选择同步为右侧方框，互斥的追加／覆盖仍保留单选语义。

### 4.3 浏览状态与空白草稿

从文件夹进入详情，返回原文件夹；从全部进入则返回全部。详情返回保留原滚动位置，退出整个随口记模块再进入时恢复全部，不持久记忆文件夹筛选。

修复详情返回置顶时，删除由顶部记录变化触发的主动滚顶逻辑，保留已有稳定列表 key 与导航恢复。不是通过清空筛选解决滚动位置问题。

新建先进入独立临时草稿，空白不写库；有效文字、标题、附件、提醒或待办可触发保存，但编辑中的新记录暂不进入浏览列表。返回后再展示有效记录，避免预测性返回途中出现空白条目闪现。仅标题或附件的记录仍应保留。

## 5. 详情与悬浮窗

### 5.1 详情最终布局

上半部分依次放录音、标题、正文，创建时间留在正文下方作为小分隔；下半部分放摘要、提醒、日程待办。

- 标题占位仅为“标题”，不写“可选”，标题与正文增加间距，不额外放“正文”小标题。
- 摘要、提醒、日程待办使用统一字号、字重和主题色小标题。
- 提醒保留原有左侧色条、右侧胶囊操作及添加行，只增加小标题。
- 语音转写成功不再显示“转写完成”；失败在正文区域使用低饱和文字反馈并保留重试。
- 生成、重新生成、停止摘要移到右上角公共菜单；分享和保存也放入该菜单。
- 链接前往按钮独立于原四按钮胶囊，空间不足时放在胶囊右上方，不挤占原工具栏宽度；圆形按钮与主工具栏复用相同玻璃／模糊材质、透明度和阴影策略。
- 主页加号补齐长按新建：今日／全部页新建日程，随口记页进入新建草稿；底栏选中填充由默认关闭的开发者开关控制。

### 5.2 悬浮窗

收起时优先显示标题，空标题则显示正文，保持紧凑高度。有效来源链接在右侧显示前往按钮；即使记录同时有音频，也只保留链接操作，录音继续在详情页使用。

展开优先显示有效摘要，没有摘要再显示正文，沿用有限行数预览。编辑提供标题、正文两个输入框，始终编辑原正文，不把摘要写成正文；后台更新不重置输入草稿。保存仅联合更新标题／正文，保护来源、附件、文件夹、提醒与待办。保存失败保留编辑状态。

## 6. 手机提取与在线 AI 的职责

| 外部解析源负责 | App 宿主负责 |
| --- | --- |
| 匹配目标页面、识别内容类型、确认内容 ID | 保存收藏、绑定随口记与任务身份、排队和取消 |
| 用受控 HTTP 或 WebView 取得目标正文与媒体地址 | 下载、真实文件类型检查、图片缩放、音轨解码 |
| 返回标题、作者、正文范围、媒体角色、顺序及限制 | 本地转写或在线音频输入、图片分批、最终摘要 |
| 缺内容、登录或目标不匹配时返回固定错误码 | 结果持久化、用户编辑保护、详情显示及统一通知 |

源采用 ZIP 内的 JSON manifest 与 JavaScript ES 模块，运行在 QuickJS 中；Kotlin 提供统一宿主能力。源不调用数据库、通知、模型 Key、Root/Shizuku 或 Shell，也不能自行指定要写入其他随口记。

同一源可包含多个平台模块；当前只保留一个源槽位。导入新源先校验再替换，失败保留旧源；成功更换或移除取消旧源任务，旧结果不能覆盖新任务。

实验室依次提供自动生成摘要、音频处理、转写文本写入正文、导入源和平台登录。导入源沿用主界面壁纸式管理卡，不做源市场或远程自动更新。平台登录入口由导入源的 loginEntries 声明；点击后通过公共底部 sheet 选择该源提供的入口，再打开对应 WebView。尚未导入源或未声明登录入口时，点击给出明确说明；有入口时显示登录选择 sheet。登录网址必须符合源声明的网络权限，登录页显示实际域名。本机 WebView 登录不等同于继承其他 App 的账号。

“自动生成摘要”默认关闭。新收藏在开关开启、有匹配源且条件满足时排队；导入源不扫描全部历史记录。当前手动生成也要求该功能开启，随后可在详情重试或停止。

## 7. 正文、图片、视频与音频

- 纯文章用实际正文；图文用文案及有序图片；混合内容保留同组关系。图片会实际下载、解码并按 AI 输入边界缩放，不只是把图片 URL 当文字发送。
- 视频优先采用源声明的完整语音音轨；仅有 BGM 不能当作视频全文。源可提供同组视频文件作为内嵌音轨回退。
- 音轨时长与视频时长的接近程度用于筛选，但不能证明音轨必含完整旁白。时长明显不足时允许改用视频内嵌音轨；不凭码率高低宣称转写更准。
- 原始 MP3、AAC 或容器音轨由手机解码为单声道 16 kHz WAV，最长三十分钟，按九十秒分段。当前不提供通用 HLS／DASH 播放清单下载、分片拼接或视频关键帧提取。
- 选择本地转写：已有 Sherpa/Qwen 模型取得真实文字，摘要请求发送文字与其他图片素材。背景音乐可能影响转写，失败不自动改走在线音频。
- 选择直接发送：在线模型收到 WAV 音频片段，先返回片段要点与逐字稿，再汇总。MP3 可以作为源下载格式，不代表将原 MP3 直接原样发送。
- 音频、图片输入使用已有模型提供器；在线服务必须支持对应素材。提取成功不等于模型处理完成，视频摘要须说明未包含全部画面信息。

## 8. AI 标题、逐字稿与用户编辑保护

最终综合结果使用 `title`、Markdown `summary`、`transcript`。摘要可含要点，但当前没有独立 `tags` 字段或标签管理，不将早期“摘要＋要点＋标签”的设想记为全部落地。

- 空白标题、平台默认收藏标题或未经用户修改的自动标题可更新为 AI 的短标题。用户自定义及分析期间改过的标题保留。
- 无效或缺失 AI 标题不丢弃有效摘要；保留纯 Markdown 响应兼容，不能猜第一行就是标题。解析源的原内容标题单独保留。
- 本地模式逐字稿来自实际 ASR；在线模式从同一次音频片段请求取得逐字原话，按顺序合并。最终汇总中的 transcript 保持空串，由宿主填回已有逐字稿，不从摘要反推。
- 取得逐字稿后先保存，再请求最终摘要；最终摘要失败仍保留已取得文字。片段缺失时显示限制，不能补造听不见的内容。
- “转写文本写入正文”默认关闭。开启后保留文案／链接，按中文句号分段追加，不添加时间轴；重试只替换未经用户修改的自动部分，分析期间正文变化时跳过追加。
- 限制说明在详情和导出共用去重规则，忽略标点与空白差异，同一限制只显示一次。
- 先保存摘要及允许回写的标题，再发完成通知；仅取得素材、请求已发出或 AI 返回空内容不算完成。

## 9. 分享、导出、数据库与同步

无本机附件时导出 UTF-8 Markdown；有图片或录音时导出 ZIP，包含同名 Markdown 与 `attachments/` 相对引用。分享使用系统菜单，保存使用系统文件选择器。

导出包含当前标题、正文、创建时间、来源链接、摘要、去重限制、未在正文重复的逐字稿、已设置提醒和本机附件。已登记但丢失的附件明确失败；分析时远端下载的临时素材不自动成为永久附件，不进入随口记附件 ZIP。

Room 显式执行 20→21 的标题／链接／文件夹迁移，再以 21→22 新增随口记关联的分析表，保留旧记录。链接摘要使用独立状态，不复用已有日程候选 `analysisStatus`。后续 AI 标题与逐字稿可选字段保存在结果 JSON，不增加破坏性迁移。

备份和 WebDAV 保留标题、来源、归属、空文件夹、有效摘要与逐字稿；不携带源脚本、登录凭据、任务 token 或下载缓存。任务绑定 memoId、随机 token、原始 URL、源内容摘要和音频模式；删除、取消、更换源或启动新任务后，过期结果不能写回。

## 10. 宿主与源的实现边界

本轮最终采用通用 JavaScript 源导入：内容提取在手机完成，摘要复用用户已配置的在线 AI。公开仓库提供宿主、协议、教学材料和自有博客示例，不内置或分发第三方平台解析源。

| 设计事项 | 最终实现 |
| --- | --- |
| 手机端提取 | 通过受控 HTTP 或 WebView 取得素材，不要求额外解析服务 |
| 源运行环境 | ZIP 内的 JavaScript ES 模块运行于 QuickJS，由 Kotlin 提供统一宿主 API |
| 分析状态 | 使用关联随口记的独立分析记录，不挤占日程候选状态 |
| AI 返回结构 | title／summary／transcript；独立标签管理仍未实现 |
| 图片分析 | 走已有多模态输入，不另建 OCR 或服务端兜底 |
| 响应与日志 | 文本响应上限为 8 MiB，错误按阶段与固定码记录 |
| 请求限制 | 保留标准端口、域名与地址限制，源声明必需权限 |

## 11. 通用失败排查

| 阶段或问题 | 宿主边界与处理方式 |
| --- | --- |
| 文本响应超限 | 上限为 8 MiB；明确失败，不截断后冒充完整正文 |
| 内容不可访问 | 源用固定错误码说明缺失、登录或验证要求；不能用导航或推荐内容代替目标正文 |
| 媒体地址不可用 | 保留 HTTPS、标准端口与权限校验；实际下载成功后仍需校验文件类型 |
| 跳转成功但无正文 | 跳转只说明取得了地址，源仍须确认目标身份和正文范围 |
| 内容 ID 判断错误 | 源按目标结构校验，不假定所有 ID 都是数字 |
| 页面资源被拒 | 检查源声明的网络权限；不能通过放宽全部域名解决 |
| 只有通用失败提示 | 用 EXTRACTING／PREPARING／TRANSCRIBING／SUMMARIZING／SAVING 阶段及固定错误码定位 |
| Worker 返回 SUCCESS | 调度完成不等于业务 DONE；有效结果须保存，通知须确认实际 POSTED |

日志保留状态、固定错误码、数量和耗时等诊断信息，不记录 Cookie、分享凭证、正文、完整媒体签名 URL 或模型响应。

## 12. 源开发与手机端运行环境

QuickJS 不是 Python、Node.js 或普通网页环境。源通过 host.http.request 和受控 browser API 请求内容；文件系统、桌面浏览器配置、Shell 与外部转码工具不属于源接口。

源代码可拆为 ZIP 内的相对 ES 模块；新增目标域名时同步检查 manifest 的匹配范围和网络权限。打包及离线检查工具只在开发环境运行，不放入手机源 ZIP，也不能代替手机端验证。

源开发时应确认链接对应的目标，返回实际取得的正文范围，区分正文图、封面、完整音轨与 BGM。素材不足时返回明确错误或限制，不凭第一条请求、最大文件或推荐内容填补缺失素材。
