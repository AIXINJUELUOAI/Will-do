## 本轮行为

- 取件类剪贴板提示显示“识别到取件码|码”，按钮为“添加取件 / 添加取餐 / 添加取票 / 添加寄件”，直接保存，无须跳回应用。
- 链接剪贴板提示显示“识别到平台链接”，按钮为“收藏”；实验室提供默认关闭的独立“剪贴板链接收藏”开关。普通权限在应用获得焦点时检查，Root / Shizuku 授权后通过既有特权监听检查。
- 普通与实况通知共用候选快照和动作。动作只携带通知键，接收端读取当时保存的候选；取件成功或已有记录后取消提示；链接收藏成功更新原通知为“已收藏到随口记”，替换为“查看”按钮，通知与按钮均直达实际记录详情，打开后取消结果通知。重复点击不会重新读剪贴板或重复入库。
- 系统文字分享和选中文字分享直接保存。命中 HTTP(S) 链接时创建链接收藏，其余文字保持原有随口记保存行为；不自动调用 AI。
- 默认标题为“抖音收藏、哔哩哔哩收藏、公众号收藏、酷安收藏、小黑盒收藏、小红书收藏、链接收藏”。所有类型可编辑可选标题。
- 有分享文案时正文第一行放清理后的文案，第二行放原链接；没有文案时只保存原链接。详情工具栏右侧独立圆形箭头打开原网址，交给系统选择对应应用或浏览器；原四个操作按钮不因链接缩窄，窄屏或双栏空间不足时箭头移至胶囊右上方，正文同步预留高度。
- 系统分享与剪贴板收藏共用事务去重；已收藏的链接不再次弹出剪贴板提示。不同短链是否指向同一内容无法离线判断。
- 文件夹单层，一条随口记最多归属一个文件夹。“全部随口记”使用 Topic，文件夹固定使用 Folder 图标。顶部三点按钮复用今日页 AppDropdownMenu，提供全部、未分组、现有文件夹、新建和管理文件夹；浏览入口与新建/管理操作之间有一条分割线；空列表也能创建。管理 sheet 一次选择一个文件夹，支持重命名和删除；重命名保留 ID、创建时间及其中记录，拒绝空名与同名；删除文件夹只将记录移至未分组。
- 设置侧边栏移除持续选中底色，保留当前导航状态供无障碍使用。
- 常态列表不在 TopBar 下方单独显示“全部随口记”筛选行，筛选入口集中在顶部三点菜单。
- 新建和移动文件夹使用 AppModalBottomSheet；新建左侧为固定 Folder，右侧输入名称。移动时可以在同一流程中新建，再返回文件夹选择；不叠加两个 sheet。文件夹通过管理 sheet 选择，在复用的新建/重命名表单中改名，删除另有二次确认 sheet，保留其中记录。
- 本版不支持自选 icon、emoji 或图片图标，不新增图标字段或改变备份/同步格式。
- 主页底栏菜单、今日、全部、随口记的选中填充受开发者开关控制，默认关闭；开启时使用官方实心图标，未选中保留现有线条图标。菜单打开时页面入口恢复线条，收起操作栏状态与预览栏共用同一规则。

- 详情返回保留原筛选；离开随口记模块（含前往设置等独立页面）重置为全部。文件夹偏好不持久记忆。
- 长按立即选中条目并进入多选，点击切换选中，支持返回退出多选及全选。右侧勾选框直接出现，语音播放按钮在多选时隐藏，不添加多选高亮背景；底部复用详情页单行胶囊工具栏，只保留官方 Done All 全选图标、移动至和默认配色的删除图标，全选动作仍可取消全选；不显示已选数量或取消按钮，返回退出多选；顶部不再显示多选行，删除通过统一底部 sheet 二次确认，红色删除按钮固定在底部。

## 平台规则表

维护文件：[QuickMemoLinkRules.kt](../app/src/main/java/com/antgskds/calendarassistant/feature/quickmemo/domain/QuickMemoLinkRules.kt)。

每个平台一条记录，普通新增只需平台名称与域名。例如：

```kotlin
QuickMemoLinkRule(
    name = "新平台",
    hosts = setOf("www.example.com", "example.com"),
),
```

- `hosts`：填完整域名，不填协议或路径。域名精确匹配；冒名子域不会被识别为正规平台。新域名只加进该平台的 `hosts`。
- `captionCleanup`：可选，按顺序删除分享套话的正则；省略即保留链接前面的文案。通常无需改动通用解析器。
- `dedupPath` / `dedupNamespace`：可选，只用于已验证的稳定内容 ID。正则第一个捕获组是内容 ID；命名空间须与其他平台区分。
- 没有特别去重规则时，保留完整路径、大小写、查询参数和片段。仅规范协议、域名及默认端口。
- 酷安已按 feed ID 去重；小黑盒 link_id 稳定性尚未验证，完整查询参数继续参与去重。
- 未登记的 HTTP(S) 网址仍可收藏，名称为“链接收藏”。规则属于应用代码，改动后重新构建 APK 生效；不需要增加设置项或新解析分支。
- 示例与回归用虚构链接，不提交用户的分享会话参数。修改规则后运行 QuickMemoLinkRulesTest 与 QuickMemoLinkParserTest。

## 随口记详情返回后列表置顶（2026-10-08）

状态：本轮已获授权修正；已移除首次进入列表便执行的自动置顶 effect，保留 `rememberLazyListState()` 和稳定条目 key，让导航恢复的滚动位置不被覆盖。尚待用户真机复核。以下证据来自修改前的静态排查，行号不是当前版本定位。

### 现象与预期

- 现象：随口记列表滚动到中间或下方，打开一条记录的详情，再返回，列表回到顶部。
- 预期：从全部、未分组或文件夹进入详情，返回时保留原筛选、原可见条目与滚动偏移。该要求属于当前浏览会话，不新增下次启动或退出模块后的长期记忆。

### 排查证据

- [QuickMemoPage.kt](../app/src/main/java/com/antgskds/calendarassistant/feature/quickmemo/ui/render/material/QuickMemoPage.kt) 第 183 行在列表内部创建 `rememberLazyListState()`；第 209–213 行的 `LaunchedEffect(topMemoKey, searchQuery)` 在列表存在记录且搜索为空时调用 `listState.animateScrollToItem(0)`。
- 这个 effect 首次进入组合也会执行，不要求 `topMemoKey` 相对上次实际改变。详情返回后列表重新进入组合时，会再次触发置顶；即使列表滚动状态已经恢复，也会被这条命令覆盖。普通数据更新造成首条记录变化时也可能触发相同逻辑。
- [MainActivity.kt](../app/src/main/java/com/antgskds/calendarassistant/MainActivity.kt) 第 741–742 行使用独立详情路由，详情页返回按钮与普通返回处理均调用 `navController.popBackStack()`（第 777–785 行），并没有在返回回调中主动要求列表置顶。
- [QuickMemoUiContract.kt](../app/src/main/java/com/antgskds/calendarassistant/feature/quickmemo/ui/contract/QuickMemoUiContract.kt) 的浏览会话保存文件夹与多选状态；详情路由被 `MainActivity` 的浏览重置逻辑明确排除。因此“返回原文件夹”和“恢复滚动位置”是两个独立问题，不应通过清空筛选来处理。

### 本轮处理与真机复核

- 已删除 `topMemoKey` 和对应 `LaunchedEffect(topMemoKey, searchQuery)`；详情返回和正文等普通更新不再要求滚到首条。不新增滚动位置持久化设置，沿用导航的保存/恢复及列表稳定 key。
- 覆盖从全部、未分组、文件夹与搜索结果进入详情后返回；分别检查返回按钮、系统返回、预测性返回完成/取消，以及反复进入同一记录。
